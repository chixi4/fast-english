# 墨墨背单词（Maimemo）启发式实现文档（v1）

> 目标：在不依赖账号体系的前提下，把“前置选词 + 复习压力 + 低摩擦判定”的核心交互迁移到本项目（FastAPI + SQLite + Jinja）中，并优先落地**前置选词（把词加入学习计划）**，解决“导入后今天要背几千词”的新手崩溃问题。
>
> 说明：墨墨的内部算法与数值并非公开，我们只能基于可观察体验与学习科学原则抽象交互模型，再用可解释的参数化方案实现。

---

## 0. 现状与痛点（对应本项目）

当前本项目的“词书导入”会为导入的每个词立即创建 `SrsCard`，导致：

- 首页/今日显示的“到期复习/新词”数量巨大（导入=立即排程）
- 新手不知道从哪里开始，心理压力过大且不可控
- 无法实现“复习优先，新词被节制”的学习节律

墨墨的关键做法是把“词库/词书内容”与“学习计划（今日会出现的词）”分离：**词可以在库里，但不一定在计划里**。

因此，我们需要引入一个新的层：**学习计划（Plan）**。

---

## 1. 核心交互模型（墨墨启发）

### 1.1 主页的“压力可视化”

首页只强调一件事：**今日待复习量**（并倒计时式减少）。

在我们这里落地为：
- 今日页只突出一个主按钮：`开始今日学习`
- 今日卡片展示：`到期复习 / 新词 / 总量（已入计划）`
- 当到期复习过高时，提示“先复习再学新词”（并可阻止发新词）

### 1.2 记忆卡片的“三段式”（检索 → 判定 → 强化）

1) **检索**：先看词（或发音/中文），不展示答案，迫使回忆
2) **判定**：翻面后展示释义/例句，出现 3 个按钮：认识 / 不确定 / 不认识
3) **强化**：在挫败时立刻给“助记/提示”（本项目可先用本地字段，后续再做 UGC）

> 本文档的落地重点是“前置选词”，三段式属于 Phase B。

### 1.3 全局去重 + 继承记忆

同一个 term 在多个词书出现时：
- 学习计划层只保留一份（全局去重）
- 词书只是“来源映射/进度统计”，不应该让用户重复劳动

我们数据库已经满足 “term 全局唯一（`Word.term unique`）”，缺的是“计划映射”与“进度统计维度”。

## 2. 我们要先做的功能：前置选词（入计划）

### 2.1 目标体验（新手 3 分钟上手）

1) 去 `词书库 /library` 导入一个词书（只导入内容，不立刻排程）
2) 回到 `今日 /`，系统提示“请把词加入学习计划”
3) 用户一键选择：
   - 每日新词：20（默认）
   - 从哪个词书开始：CET4（或刚导入的词书）
4) 点击 `开始今日学习`，今日只出现少量新词 + 已到期复习

### 2.2 关键规则（墨墨风格但可解释）

- **复习优先**：如果今日到期复习超过阈值（例如 200），则暂停发新词
- **新词节制**：每日新词默认 20，可调 5~50
- **混合队列**：会话里穿插复习词与新词（Phase B；Phase A 可先 “复习 → 新词”）
- **一键续杯**：今天新词学完后，可以手动“再加入 10 个新词”（但要明确提示会增加未来复习压力）

## 3. 数据模型设计（最小可用）

> 当前表：`Word / Deck / DeckWord / SrsCard / SrsReviewLog / Mistake / Simulation`

### 3.1 新增表：学习计划

**Plan**
- `id`
- `name`（默认：`默认计划`）
- `daily_new_limit`（默认 20）
- `daily_review_limit`（默认 200，可选：0=不限制）
- `suspend_new_when_due_over`（默认 200）
- `created_at / updated_at`

**PlanDeck（计划与词书的绑定/顺序）**
- `id`
- `plan_id`
- `deck_id`
- `priority`（越小越优先）
- `created_at`

**PlanWord（词进入计划的时间与来源）**
- `id`
- `plan_id`
- `word_id`
- `source_deck_id`（从哪个词书加入；用于进度统计）
- `added_at`
- `status`（active/paused/done；先做 active 即可）

### 3.2 重要约束

- `Word` 仍然全局唯一（term 去重）
- `SrsCard` **只为已入计划的词创建**（这是本次改造的关键）
- `DeckWord` 仅用于“词书包含关系、章节、排序”，不代表学习状态

## 4. 业务流程（入计划与排程）

### 4.1 导入词书（仅入库，不排程）

当前实现里导入会 `ensure_srs_card()`，需要改为：

- `library/import`：导入 `Word` + `DeckWord`
- 不创建 `SrsCard`
- 导入完成后跳回今日页，提示“已导入词书，下一步：加入学习计划”

> 手动添加单词可以默认“直接入计划”（保留“立刻可背”的直觉）。

### 4.2 入计划（选择“今天要发多少新词”）

入计划的本质是：为选中的 `word_id` 创建 `PlanWord`，并创建 `SrsCard(due_at=now)`。

最小实现策略：

1) 用户在“今日”或“词书详情”点击：`加入学习计划（加入下一批 N 个）`
2) 系统按 `DeckWord.position` 升序挑选未入计划的词（若无 position 则按 term）
3) 对每个词：
   - 创建 `PlanWord`
   - 创建 `SrsCard`（首次 due=now，FSRS state=Learning）

### 4.3 今日学习队列生成

`/review`（今日学习页）选词优先级：

1) 复习队列：`SrsCard.due_at <= now`
2) 新词队列：`SrsCard.last_reviewed_at is NULL`（且今日新词未超 `daily_new_limit`）

> Phase A：先做 1)；当 1) 为空时再做 2)。Phase B 再做“混合穿插”。

## 5. 页面与交互落地（结合当前网页结构）

### 5.1 今日页 `/`（已完成基础版，需升级“计划状态”）

新增模块（当 `total==0` 但已导入词书时）：

- “你已导入词书，但还没加入学习计划”
- 主按钮：`从词书加入 20 个新词`
- 次按钮：`去词书管理`

### 5.2 词书列表 `/decks`

每个词书增加两个数字：
- 词书总词数（已存在）
- 已入计划/未入计划（新增）

提供按钮：
- `加入计划：下一批 20`

### 5.3 词书详情 `/decks/{id}`

增加“进度条/统计”：
- 总词数
- 已入计划
- 已复习（last_reviewed_at not null）

增加“加入计划”控件：
- 输入：加入数量 N（默认 20）
- 选项：跳过已在计划/已学会的词（默认开）

### 5.4 复习页 `/review`（Phase B）

在现有 Again/Hard/Good/Easy 的基础上：

- 卡片默认只显示 term（或发音），点击“显示答案”后才出现释义与按钮
- 按钮文案：认识/不确定/不认识
- 增加“撤销上一步”（undo）：回滚 `SrsReviewLog` 的最新一条并还原 `SrsCard`

---

## 6. 数值与默认配置（先可用，再迭代）

建议默认值：

- `daily_new_limit = 20`
- `daily_review_limit = 200`
- `suspend_new_when_due_over = 200`
- “再来一批新词”每次固定 10（并提示风险）

这些数值并不宣称等同墨墨，而是：
- 对新手足够温和
- 能把“复习压力”稳定在可控区间

---

## 7. 与本项目差异化（错词重组 + 实战短文）的衔接

墨墨的“错词强化”更多是多次复现，本项目的护城河是：

> 错词 → 语境短文 → 阅读做题

衔接点：

- 当用户在 `/review` 中点“不认识”，自动进入错词池（已实现 Mistake）
- 当今日学习结束，提示：`用今天的错词生成一篇实战短文`

## 8. 实施计划（建议按 PR 拆）

**PR-1：引入学习计划（核心）**
- 新增 `Plan/PlanDeck/PlanWord`
- 导入不再自动创建 `SrsCard`
- 提供“加入计划（下一批 N）”接口与页面入口
- 今日页展示“计划内统计”

**PR-2：今日学习会话（新手化）**

- 认识/不确定/不认识 三按钮
- undo（撤销上一步）

**PR-3：全局去重体验完善**
- 跨词书加入计划时，自动跳过已入计划/已学习词
- 词书进度统计更准确（已入计划、已学习、剩余）

---

## 9. 验收标准（MVP 级）

1) 导入 CET4 后，“今日到期复习”不会飙到几千；默认只显示 0 到期 + 0 新词（直到用户加入计划）
2) 用户在词书页一键“加入 20 个新词”，今日开始学习只出现这 20 个（不会出现全量）
3) 词书详情能看到“已入计划/剩余”统计
4) 复习仍可正常排程（FSRS），错词仍可生成实战短文（现有功能不回退）
