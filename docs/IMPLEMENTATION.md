# 背单词应用（错词重组 + 实战模拟）实现文档

## 1. 背景与核心理念
### 1.1 传统痛点
市面常见背单词产品通常给“静态例句 + 释义 + 选择题”，用户错了就重复同一句话。但考试场景（阅读理解/完形/翻译）里，单词往往被埋在长难句、指代、转折、信息密集段落中；**单词是否“会”，最终体现为能否在语境中理解并完成题目**。

### 1.2 创新点（差异化）
**错词重组 + 实战模拟**
- 把用户“记不住/做题错”的词，组成一个“错词篮”
- 用AI生成一篇符合指定难度（初中/高中/四六级/考研）的阅读短文，要求自然覆盖这组词
- 基于短文自动生成题目（阅读理解 + 词汇题/完形式cloze），并判分与讲解

### 1.3 可借鉴的前人经验（学习科学/产品方法）
你要做的不是“背单词App里加了个AI作文”，而是在**学习机制**上对齐以下已被反复验证的原则：
- **检索练习（retrieval practice）**：用“回忆/做题”替代“反复看”，长期记忆更稳。
- **间隔重复（spaced repetition）**：分散复习比集中复习更有效；典型算法如 SM-2、FSRS 等。
- **语境化与多语境暴露**：高质量语境与多样语境可提高词汇学习效率；但“纯阅读的偶得学习”效应有限，需要结合显性练习与测验。

（参考阅读建议见文末“资料与链接”。）

## 2. MVP范围定义（最小可用）
### 2.1 必做（MVP）
1) 单词库：新增/删除/搜索
2) 词书（Deck）：创建/查看/按词书复习
3) 批量导入：CSV/TSV/TXT + 词书/章节字段 + 重复策略（跳过/更新）
4) 复习排程：FSRS（Again/Hard/Good/Easy）→ 自动安排下一次到期；Again 记录为错词事件
5) 错词篮：选择若干错词 + 难度 → 生成短文 + 题目
6) 做题与判分：提交答案 → 得分 + 每题解析
7) 成本/稳定性：生成结果入库缓存；生成失败可重试；无Key可用Mock跑通

### 2.2 暂不做（后续迭代）
- 账号体系、多端同步、离线包
- 发音、图片记忆、OCR拍照导入
- 题目质量评估与纠错闭环（人审/众包/自动一致性检查）

## 3. 用户画像与核心流程
### 3.1 目标用户
- 以考试为目标：中高考、四级/六级、考研英语
- 能接受“做题”而非只背卡片

### 3.2 核心用户流程（MVP）
1) 添加单词（或未来导入）
2) 复习时点击“没记住” → 进入错词篮
3) 在错词篮选 5~20 个词，选择难度 → 生成短文与题目
4) 做题 → 判分 → 回看解析
5) 继续下一轮（错词篮可滚动更新）

## 4. 数据模型（建议）
MVP可以先用SQLite，后续迁移Postgres。

### 4.1 表设计（示例）
**Word**
- `id`
- `term`（唯一）
- `definition`（中文释义/备注）
- `example`（可选）
- `tags`（可选）
- `correct_count` / `wrong_count`
- `last_reviewed_at`

**Mistake**（错误事件）
- `id`
- `word_id`
- `created_at`

**Simulation**（一次实战模拟）
- `id`
- `level`（junior/senior/cet4/cet6/kaoyan）
- `target_terms_json`（list[str]）
- `passage`
- `questions_json`（结构化题目：choices/answer/explanation…）
- `created_at`

**Deck**（词书/单词书）
- `id`
- `name`（唯一）
- `description`
- `created_at`

**DeckWord**（词书-单词关系）
- `deck_id`
- `word_id`
- `chapter`（可选：Unit/章节）
- `position`（可选：排序）

**SrsCard**（FSRS卡片状态）
- `word_id`（主键）
- `state` / `step` / `stability` / `difficulty`
- `due_at` / `last_reviewed_at`

**SrsReviewLog**（复习日志）
- `word_id`
- `rating`（Again/Hard/Good/Easy）
- `reviewed_at`
- `duration_ms`（可选）

### 4.2 指标（建议跟踪）
MVP先做最小：正确/错误次数即可。后续可扩展：
- `mastery`（掌握度）= f(最近正确率、间隔、反应时)
- `in-context accuracy`：词汇题正确率 vs. 阅读题正确率
- 词汇覆盖率：生成短文是否包含目标词、是否自然用法（自动检测）

## 5. AI生成：方案与细节
### 5.1 输入（Prompt前置处理）
从错词篮抽取：
- `term`
- `definition/备注`（非常关键，用于减少AI误用词义）
- 可选：词性、常见搭配、错误类型（选错义项/拼写/辨析）

### 5.2 输出（强结构化）
要求模型输出**严格JSON**，字段固定：
- `passage`: string
- `questions`: list[
  - `id`
  - `type`（vocab_in_context/cloze/main_idea/detail/inference…）
  - `stem`
  - `choices`（固定4个）
  - `answer_index`（0-3）
  - `explanation`
  - `target_term`（可选，用于定位该题训练哪个错词）
]

为什么要结构化：
- 可判分、可统计、可追踪某个词的训练效果
- 便于做质量检测与重试（JSON不可解析/漏词 → 自动重试）

### 5.3 难度控制（可操作化）
不要只写“难度=考研”，而要给可执行约束：
- 篇幅（词数范围）
- 句法：从句数量、长句占比
- 主题与体裁：校园/科普/新闻/社科短评（更贴近考试阅读）
- 出题分布：词汇题占比、推断题占比、细节题占比

### 5.4 质量与安全护栏
**必做自动检查**
- 覆盖检查：每个目标词是否至少出现一次（大小写不敏感，词边界匹配）
- JSON校验：可被 `json.loads` 解析 + 通过Schema校验

**建议增加（后续）**
- 词义一致性检查：让第二个“校对模型”判断目标词用法是否符合给定释义
- 题目可解性检查：是否存在唯一正确选项、是否与短文一致
- 生成缓存：同一组词 + 同一难度可复用，控制成本

### 5.5 成本控制与体验
- 限制一次生成的词数（比如 8~15），太多会导致“硬塞词”与成本暴涨
- 允许“批次”生成：一次生成短文 + 6题；下一次再生成另一篇
- 给用户提供“重生成/换难度/减少词数”的快速入口

## 6. 题型设计（建议组合）
### 6.1 词汇题（语境型）
目标：训练“词义/搭配/语气/词性转换”。
- 题干引用短文句子（或相邻句），问划线词在此处最接近哪一义项
- 选项设计要有干扰项：近义词辨析/词性混淆/语气不符

### 6.2 Cloze（完形式）
目标：迫使用户把词放到正确句法位置。
- 挖空目标词或其关键搭配
- 选项设置包括：同形词、近义词、搭配错误选项

### 6.3 阅读理解（主旨/细节/推断）
目标：让用户“在做题中遇到错词”，形成考试迁移。
- 主旨题：考段落中心
- 细节题：可定位
- 推断题：跨句信息整合

题量建议（MVP默认 6 题）：
- 3 题词汇/完形（覆盖错词）
- 3 题阅读理解（主旨/细节/推断各1）

## 7. MVP技术架构（建议实现）
### 7.1 推荐落地（最省事的全栈方式）
- 后端：FastAPI
- 数据库：SQLite（文件）
- 前端：服务端渲染（Jinja2）或 HTMX（后续可加）
- AI：OpenAI-Compatible `POST /chat/completions`（兼容多家）

### 7.2 模块拆分
- `app/models.py`：ORM模型
- `app/db.py`：Session/建表
- `app/ai.py`：Prompt与生成（含JSON校验/漏词校验/重试）
- `app/main.py`：路由与页面

## 8. 迭代路线图（从MVP到可用产品）
### Phase 1（1-2周）：MVP可用
- 词库/复习/错词篮/生成/判分闭环
- 生成结果缓存、重试、Mock模式

### Phase 2（2-4周）：学习效果提升
- 引入SRS排程（FSRS/SM-2），做“到期复习”
- 错误类型标注：词义错/搭配错/阅读错
- 双模型校验：生成 + 校对（质量显著提升）

### Phase 3（1-2月）：内容与增长
- CSV导入导出、词库标签体系
- 多篇短文同主题“连载式训练”（更像真题套卷）
- 数据看板：每周错词热力图、题型薄弱点

## 9. 非功能需求与风险清单（建议）
### 9.1 AI内容风险
- **误用词义/不地道用法**：输入里必须带释义/备注；后续加“校对模型”做一致性检查。
- **漏词/硬塞词**：生成后做覆盖检测；超过阈值就提示用户减少词数/重生成。
- **题目不可解/多解**：后续加自动检查（唯一正确选项）或让校对模型输出“可解性判定”。

### 9.2 产品/学习风险
- **只做题不回顾**：判分页必须展示解析与回链到“单词卡片/释义/例句”。
- **难度失控**：给每档难度写可执行约束（词数/长句占比/体裁），并允许用户一键降档。

### 9.3 工程风险
- **成本不可控**：限制每次目标词数量；缓存生成结果；对重复组合复用。
- **Key泄露**：只放在服务端环境变量；前端不保存；日志里不要打印Key或完整请求。

## 10. Prompt模板（可直接用）
建议固定成“系统提示 + 用户提示”，并将难度/词表/题量参数化。

系统提示（示例，中文便于约束）：
- 角色：英语考试出题老师
- 约束：只输出严格JSON，不要Markdown；choices固定4个；answer_index 0-3；每题explanation 1-2句

用户提示（骨架）：
1) 难度描述（词数/句法/体裁）
2) 硬性要求（必须包含全部目标词，语境自然）
3) 输出Schema样例（字段名固定）
4) 目标词清单（term + 释义/备注 + 可选例句）

## 11. MVP页面与接口清单（与本仓库一致）
页面：
- `/` 仪表盘
- `/words` 单词库（新增/删除/搜索）
- `/decks` 词书列表（创建/删除）
- `/decks/{id}` 词书详情
- `/review` 复习（FSRS：Again/Hard/Good/Easy，支持按词书过滤）
- `/mistakes` 错词篮（选词 + 生成）
- `/simulations` 短文库（最近生成）
- `/simulations/{id}` 做题
- `/simulations/{id}/grade_async` 判分

接口（表单POST）：
- `POST /words` 新增单词
- `POST /words/import` 批量导入（支持词书/章节/重复策略）
- `POST /words/{id}/delete` 删除单词
- `POST /decks` 创建词书
- `POST /decks/{id}/delete` 删除词书（只删关联，不删单词）
- `POST /review/{id}` 提交复习结果（rating=again|hard|good|easy）
- `POST /simulations/generate` 生成短文+题目
