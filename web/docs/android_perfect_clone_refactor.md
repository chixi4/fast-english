# 安卓应用完美复刻网页重构总文档

## 一 文档定位
这份文档只服务一个最终目标，也就是把安卓应用完整且精确地复刻为网页应用。这里的完整不是功能数量接近，而是功能行为、状态流转、数据结果、界面结构、文案细节和交互反馈都与安卓保持一致，并且在同一组测试路径下得到同样结论。

执行基线时间为 2026-02-23，项目目录为 `web`，当前主核验文件为 `web/screenshot_compare/visible52_features.json`，总核验点数为 52。

## 二 最终目标定义
为了避免目标模糊，本次重构把完美复刻定义为五个同时满足的条件，任何一个条件不满足都视为未完成。

1. 功能一致
52 个可见功能点全部可执行，且执行结果与安卓一致。

2. 状态一致
同一功能点在同一前置状态下，网页必须进入与安卓相同的页面和子状态，不能出现功能页错位。

3. 数据一致
同一输入数据在安卓与网页得到同一输出结构，包含学习进度、生词本状态、今日新词、学习统计与实验室配置。

4. 视觉一致
同一功能点对应的安卓截图与网页截图在人工视觉审阅中判定一致，包含布局层级、字体大小、控件尺寸、留白关系、按钮位置、图表信息密度和文案可读性。

5. 回归稳定
连续三轮全量实测都通过，且第三轮与前两轮结果一致，不出现偶发通过。

## 四 重构总策略
### 4.1 总原则
1. 安卓源码和安卓实机表现是唯一标准，不以网页现状为基准。
2. 先修状态链路，再修视觉系统，最后做逐项收口。
3. 每次改动必须带可复现证据，证据包括截图对、日志和审阅结论。

### 4.2 技术路线
本轮不做零散修补，而是按分层重构推进，确保后续每次修改都可控。

1. 路由与状态层重构
建立统一页面状态机，明确每个功能点的前置条件、跳转路径和退出路径，彻底消除功能页错位。

2. 页面骨架层重构
统一安全区、顶部栏、内容区和底部栏的高度规则，使网页结构先与安卓对齐，再叠加具体业务组件。

3. 视觉规范层重构
把字体、字号、行高、圆角、边框、间距、按钮尺寸沉淀为统一变量，禁止各页面自定义偏移。

4. 组件行为层重构
把学习卡片、查词结果卡、词书详情弹窗、统计图卡、实验室配置卡做成安卓一比一组件模板，并由同一参数驱动。

5. 数据流与副作用层重构
统一学习进度写入、生词本变更、今日新词选取、学习统计刷新和实验室配置存储的执行时序。
